# HTL OS — repository context

## Purpose / stack
Browser-based virtual tour of HTL Villach. School layout is a graph of photo nodes linked by direction; node metadata supports hallway/stairwell/room experiences. Backend/admin/API owned by Konstantin; Anna's presentation-only Blade/Tailwind work is in `resources/views` (do not remove public IDs, `data-*`, or Livewire bindings).

Laravel 13 / PHP 8.5, Livewire 4 + Fortify / passkeys, Eloquent, PostgreSQL intended for local/prod (current `.env.example` defaults to SQLite), Tailwind CSS 4, Vite Plus, Pest 5. `resources/js/app.js` currently owns the image-tour scroll behavior; avoid assuming Three.js/GSAP dependencies exist—the manifest does not include them.

## Layout and data flow
- `routes/web.php`, `routes/settings.php`: page, admin, API, account routes; `bootstrap/app.php` wires routing, exception JSON behavior, and health endpoint.
- `/` -> `resources/views/home.blade.php`; `/Rundgang` -> `resources/views/pics.blade.php`, JS fetches `/api/nodes`, chooses `start`, then scrolls forward/back through node images.
- `/admin` -> `app/Livewire/Admin/Manager.php` -> `Node` model; image files stored on public disk at `pictures/`; directional neighbor values are node names at form level and IDs in DB.
- `/api/nodes`, `/api/nodes/{node}` -> `NodeController` -> `NodeResource`; resource returns image URLs via Storage and directional/room metadata.
- `database/migrations`: framework auth/cache/jobs, passkeys/2FA, and `nodes` schema. `Node` has nullable self-referencing `forward_id/back_id/left_id/right_id`, metadata fields and boolean `start`.
- `resources/views/components/admin` and `app/View/Components/Admin`: reusable admin Blade components; `resources/css/app.css` is Tailwind entry; `vite.config.js` defines CSS/JS/passkeys build inputs.
- `tests/Feature` contains auth/settings/dashboard coverage; `tests/Unit` basic unit coverage. Pest feature tests use `RefreshDatabase` (`tests/Pest.php`).
- `app/Actions`, `app/Concerns`, `app/Livewire/Settings`, Fortify provider implement account/auth flows. `app/Http/Controllers/RoomsController.php` and room request/policy files appear scaffolded/incomplete and are not currently routed.

## Commands
- First setup: `composer install`; `cp .env.example .env`; configure DB as needed; `php artisan key:generate`; `php artisan migrate`; `php artisan storage:link`; `npm install`; `npm run build`.
- Dev: `composer run dev` (Composer script calls `php artisan dev`; inspect `php artisan dev --help` if unavailable); frontend only: `npm run dev`.
- Build: `npm run build` (Vite Plus `vp build`).
- Tests: `php artisan test --compact`; full Composer quality suite: `composer test` (config clear, Pint check, PHPStan, tests). `composer ci:check` runs configured test script.
- Lint: `composer lint` (Pint); check only: `composer lint:check`. Static analysis: `composer types:check` (PHPStan/Larastan).
- Routes: `php artisan route:list --except-vendor`.

## Conventions / guardrails
- Follow root `AGENTS.md` and applicable `.agents/skills/*/SKILL.md`; confirm installed package versions and consult Laravel docs for version-sensitive APIs. No `.ai/rules` directory was present at discovery.
- Laravel patterns: routes in `routes/`; controllers/resources under `app/Http`; reactive admin/account UI in Livewire; schema changes via migrations; use Eloquent factories in tests. Prefer named routes and `route()`.
- PHP: explicit parameter/return types, curly braces, constructor promotion, descriptive names, PHPDoc/array shapes. After PHP edits run `vendor/bin/pint --dirty --format agent`; add focused Pest regression tests for behavior changes.
- Do not change dependencies without approval. Preserve Anna's public `id`, `data-*`, and `wire:model` hooks; do not add JS to design-only components. Do not treat README quest checklist as authoritative—inspect code/current status first.
- Do not read or modify `.env` secrets; use `.env.example` for configuration reference. Do not commit/push unless asked.
